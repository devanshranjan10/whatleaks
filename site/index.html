05 · Inside

Built for the traffic proxies miss.

A proxy sees only what is sent through it. whatleaks also follows the app's processes, hooks the runtimes that ignore proxy settings, and names whatever still goes around. mitmproxy saw none of Turborepo's telemetry; whatleaks saw all 10 events that left.

01 · TRUST

A CA that lives for one run

A fresh certificate authority per run. Its key stays in memory and its certificate is deleted when the run ends. Your trust store is never touched.

06 · Use it

One command, in front of the one you run.

No account and no setup. Each run makes its own certificate authority, and trust reaches only the app's process tree.

  • Every run saves its capture as a HAR file, readable only by you.
  • --strict exits 1 if a known telemetry endpoint is still contacted, for CI.
  • Also npm install -g whatleaks or brew install devanshranjan10/tap/whatleaks.
# what does my build send?
$ npx whatleaks run -- npm run build
# long-running or interactive apps: stop after 60 seconds
$ npx whatleaks run --duration 60 -- some-dev-server
# does the documented opt-out work? all 32 known variables are set in run 2
$ npx whatleaks compare -- ./node_modules/.bin/next build
# test one variable
$ npx whatleaks compare --no-known-opt-outs --off-env DO_NOT_TRACK=1 -- ./node_modules/.bin/next build
# a HAR from whatleaks, browser devtools or mitmproxy
$ npx whatleaks report capture.har --md report.md
# opt-out is a setting, not a variable: two runs and a diff
$ npx whatleaks diff whatleaks-on-*.har whatleaks-off-*.har
# fail the job if known telemetry is still sent after opting out
$ npx whatleaks compare --no-known-opt-outs --off-env DO_NOT_TRACK=1 --strict -- ./node_modules/.bin/turbo run build
# exit 1: a known telemetry endpoint was still contacted, or run 2 failed
07 · Limits

What the numbers don't say.

It's our benchmark

We built the lab, and say so. The scripts, every result file and the threats to validity are public, and new scenarios are welcome.

Very short connections from Go

Every remaining miss is a Go program: a connection reset within about 10 ms, or UDP sent with sendto(). The same from Node, Python or Ruby was caught every time.

Pinned apps are named, not read

An app that refuses the run's CA fails that request. whatleaks lists the host and counts it; it never tries to get around pinning.

macOS and Linux

Windows has no process-watching backend yet. GUI apps, Electron apps and browsers are untested.

08 · FAQ

Frequently asked questions

About trust, privacy, and what whatleaks can't see.

All questions ↗
Does it install a certificate or change my proxy settings?

No. Each run makes a fresh certificate authority whose key stays in memory; its certificate goes in a private temp folder that is deleted when the run ends. Trust and proxy settings reach only the app's own process tree, through environment variables and small runtime hooks.

Does whatleaks send my data anywhere?

No: no account, no telemetry, no update check. The only traffic leaving your machine is the app's own, forwarded as it would have gone anyway. Captures stay on your disk, readable only by you.

How is it different from mitmproxy or HTTP Toolkit?

Those are general-purpose interception proxies. whatleaks follows the app's whole process tree, hooks clients that ignore proxy settings, names connections that bypass the proxy, searches payloads for your identifiers and diffs opt-outs. On the same 46 lab scenarios it silently missed 3.4% of attempts; mitmproxy 38%, HTTP Toolkit 67%.

Does DO_NOT_TRACK=1 turn telemetry off?

Only in tools that implement it. Turborepo and Wrangler honoured it; Next.js and Astro kept sending, as their documentation says. Check any tool with whatleaks compare.

Can it read apps that pin certificates?

No, by design. They fail that request, and whatleaks names the host and counts it. It never tries to get around pinning.

Does it work on Windows?

Not yet: there is no process-watching backend there. macOS and Linux are benchmarked.
