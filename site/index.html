01 · What it finds

Find out what it says about you.

Every payload is decoded and every field inventoried. whatleaks searches it for this machine's identifiers, raw and hashed, and flags the ids an app keeps between runs.

It looks for you in every request

  • Your username, hostname, home path, MAC address, machine id and git email, raw or as md5, sha1 and sha256 hex or base64.
  • Ids that repeat across requests, and ids that stay the same between runs: stored by the app, so they can link your runs together.
  • Where each field appeared and how often, with a redacted sample you can post.

04 · How it works

Built for the traffic proxies miss.

A proxy sees only what is sent through it. whatleaks also follows the app's processes, hooks the runtimes that ignore proxy settings, and names whatever still goes around.

A CA that lives for one run

Each run makes a fresh certificate authority. Its key stays in memory and its certificate is deleted when the run ends. Your system trust store is never touched.

The whole process tree

Child processes are followed, including detached helpers that keep sending after the app exits. --duration and Ctrl-C stop them all.

Hooks for Node, Python and Ruby

Small preloads route clients that ignore proxy variables, like node:http2 and aiohttp, and report each direct socket as it opens.

Names what goes around

Connections that bypass the proxy are listed by address and process: netstat on macOS, /proc on Linux. Pinned clients are named and counted, never broken into.

Every field, inventoried

JSON, NDJSON, form and binary bodies are decoded. 69 known telemetry hosts carry a source link; keyword guesses are marked ? and never count toward a verdict.

Reports you can post

Your identifiers become labels, secrets become ‹redacted›, ids become aliases. The raw HAR stays on your machine, readable only by you.

05 · Limits

What it can't see.

Measured, not guessed. The numbers are in the benchmark.

Apps that refuse the CA

Pinned clients, and Go programs on macOS (they read only the keychain), fail that request. whatleaks names the host and counts it. It never tries to get around pinning.

Very short sockets from native code

Go, Rust or C connections that skip the proxy are found by polling. One reset within about 10 ms is often missed (Go in the lab: caught 10 to 30% of the time), and UDP sent with sendto() is never seen.

Windows

No process-watching backend yet, so it is untested there. macOS and Linux are benchmarked.

Apps you don't launch

Only processes started through whatleaks are watched. GUI apps, Electron apps, browsers and system daemons were not tested.

Exact matching only

Salted hashes of your identifiers can't be recognised. Redaction is pattern-based, so read a report before you post it.

It's our benchmark

We built the lab. Every script and result file is public, and the threats to validity are written down next to the numbers.
